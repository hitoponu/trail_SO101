## 今回やりたいこと

**4 コンテナ構成を 1 イメージ 1 コンテナ 1 launch に統合しました**（`docker/robot/`）。
統合そのものは Mac のモックで検証済みです。**実機でしか確かめられないのは
「異常終了したときに機体を止められるか」だけ**で、それが今回の主目的です。

### ★ なぜこれが要るのか（背景）

停止処理はすべて Python の `finally` にあります。分岐しているのは
**「`finally` に到達できるか」だけ**です。

| 経路 | アームのトルク | ホイール |
| --- | --- | --- |
| `Ctrl+C` / SIGTERM / Python 例外 | OFF → 落ちる | 速度ゼロ + トルク OFF |
| **SIGKILL**（`docker kill` / OOM / 強制削除） | **ON のまま → 凍る** | **最後の指令速度で回り続ける** |

STS3215 に**コマンドウォッチドッグはありません**。プロセスが消えてもサーボは
最後に受け取った `Goal_Velocity` を保持し続けます。

4 コンテナ構成では「アームのコンテナだけ SIGKILL すれば姿勢が凍る」という手が
使えました。**1 コンテナではベースのドライバも道連れになり、ホイールが回り続けます。**
そこで復帰専用コマンド `release_all` を作りました。**これが効かないなら
1 コンテナ化は安全側に成立しません。**

### 手順 2 🔴 H-1: `release_all` が実際にトルクを落とすか（**今回いちばん重要**）

> **★ これが通らなければ手順 3 に進まないでください。**
> 手順 3 はわざと機体を暴走させる手順なので、止める手段が確認できていない
> 状態でやってはいけません。
>
> **★ 人がアームを支えてください。**
> トルクが切れる瞬間が **2 回**あります。**どちらも先に手を添えてから**行うこと。
>   1. **`make run` の起動直後**（下記 2-a）。ブリッジは接続時に
>      `disable_torque()` → 現在位置を `Goal_Position` に書く → 再投入、
>      という順で初期化するため、**一瞬だけ脱力します**
>      （`so101_bringup/lerobot_backend.py` の `_connect`）。
>   2. 2-e の `make release`（こちらは切りっぱなし）。
>
> **★ 車輪は浮かせたままにしてください。** この手順では `/cmd_vel` を出しません。
> **★ ベース（12V）の電源も入れてください。** `make run` は `base_driver` も
> 起動するので、無給電だとベース側がエラーになります。また 2-d / 2-e は
> ホイールのバスも読むので、無給電だと「解放を確認できなかった」と報告されます。

#### 2-a. 通常起動してアームを畳む

アームとベースの電源を入れます。

```
1. 人がアームを支える     ← ★ 起動直後に一瞬トルクが抜けます
2. make run
3. 起動しきって姿勢が保持されたのを確認してから手を放す
```

```bash
cd docker/robot
make run           # ★ 前面で走ります。この端末は開いたままにする
```

別ターミナルで:

```bash
make stow          # アームを低く畳む
```

> **★ launch が動いている間はシリアルバスを触りません。**
> Feetech のバスは半二重で、マスタは 1 つしか居られません。launch がポートを
> 開いたまま別プロセスが読みに行くと**パケットが混線し、ブリッジが通信異常と
> 判定してトルクを切ります**（＝アームが落ちます）。「読むだけ」でも送信が
> 要るので安全にはなりません。
> `make release*` にはこれを止める guard を入れてあるので、
> 誤って叩いても `ERROR: コンテナ robot が動いています` で止まります。
> トルクが入っていることは `make stow` でアームが動いたことで確かめられます。
> 数値での確認は 2-d（launch が死んでポートが空いてから）に行います。

#### 2-b. ★ わざと SIGKILL する

```bash
docker kill robot
```

**この瞬間に何が起きたかを観察してください。**

- アームは**その姿勢のまま凍る**はずです（脱力しない）
- 手で押してみて、**抵抗があるか**を報告してください
  （★ 無理に力を入れないこと。軽く触れる程度で）

#### 2-c. 死んだコンテナを片付ける

```bash
docker compose -f compose.yaml down
docker ps -a --format '{{.Names}}'     # robot が残っていないこと
```

#### 2-d. ★ トルクがまだ入っていることを読む

```bash
make release-check
```

**6 軸すべて `Torque_Enable=1` のはずです。** ここが `0` なら
「SIGKILL でトルクが残る」という前提が間違っていたことになるので、
**そこで止めて報告してください**（設計を見直します）。

> ★ **`make: *** [release-check] Error 1` と出ますが、この時点では正常です。**
> 終了コードは「全 ID が脱力済みか」を表すので、トルクが入っているうちは
> 必ず 1 になります。失敗と受け取らないでください。
>
> ★ ホイール（ID 7/8/9）も一緒に読みます。ベースに給電していれば
> `Torque_Enable=1`、`stop()` 済みなら `0` です。どちらでも構いませんが、
> **読めない**（`★ 読み出せない`）なら 12V が来ていないので確認してください。

#### 2-e. ★ 解放する（**人がアームを支えてから**）

```
1. 人がアームを支える              ← ★ 先に手を添える
2. make release
3. 確認プロンプトに y と答える
4. アームが脱力するのを確認してから手を放す
```

```bash
make release
```

**報告してほしいもの**:

- 2-d と `make release` の出力**全部**
- 2-b でアームが凍ったか（手で押したときの抵抗の有無）
- `make release` の最後が `すべて解放を確認しました (Torque_Enable=0 を読み戻し済み)`
  になったか
- アームが実際に脱力したか（**読み戻しの値と体感が一致したか**）

> ★ **ここがこの依頼の核心です。** `Torque_Enable=0` と読めたのに実際には
> 脱力していない、あるいはその逆があれば、**それが最も重要な報告です**。

#### 2-f. 片付け

アームの電源を切ってください。

#### 3-a. アームを使わずにベースだけ起動する

```bash

                   #   （旧スタックのコンテナが生きていないか guard が確認する）

    backend:=mock start_rviz:=false start_camera:=false
```

`backend:=mock` なのでアームのシリアルは開きません。ベースと LiDAR は実機です。

#### 3-c. ★ SIGKILL する

```bash
docker kill robot
```

**★ ここで車輪が回り続けるはずです。** これが確かめたいことです。

- **回り続けましたか？ 止まりましたか？** 何秒くらい観察したかも報告してください
- ★ **止まった場合はそれも重要な報告です**（前提が違っていたことになる）

> **危ないと感じたら迷わず物理スイッチを切ってください。**
> その場合は「物理スイッチで止めた」と報告してくれれば十分です。

#### 3-d. 止める

```bash
docker compose -f compose.yaml down
make release-wheels
```

`make release-wheels` はアームに触れないので確認プロンプトは出ません。

> ★ **駆動が切れるだけで、ブレーキはかかりません。**
> `release_all` は `Goal_Velocity=0` を書いた直後にトルクを切るので、
> 車輪は**惰性でしばらく空転します**（浮かせてあるので特に長く回ります）。
> 「指令が消えて自然に止まる」なら成功です。**これを食い違いとして
> 報告しないでください。** 食い違いとは「`Torque_Enable=0` と読めたのに
> **駆動され続けている**」ことです。

**報告してほしいもの**:

- 3-c で車輪が回り続けたか（**秒数も**）
- `make release-wheels` の出力全部
- **実際に駆動が止まったか**（惰性の空転は成功。読み戻しの値と体感が一致したか）
- 物理スイッチを使わざるを得なかったなら、その旨

### 手順 5 🟡 H-5: 実機で `Ctrl+C` 停止

> **★ 車輪は浮かせたまま。ベースとアームの電源を入れる。**
